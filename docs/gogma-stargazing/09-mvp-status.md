# MVP 实现与验证记录

日期：2026-10-26。业务版本 0.1.0；SDK 0.9.3。

## 实现范围

两类玩家入口已落地，共用 Reset 预测和执行流程。包括：样本编辑、有效候选池检查、范围搜索、暂停／取消／持久化续搜、额外样本核对、回档或继续位置确认、五条选填需求与同类向高级匹配、多武器最短路线与同格冲突、单次垫刀计数与撤回、结果采用／拒绝／偏差暂停、最新游戏保存检查点、GSF1／GSF2 与完整 JSON 文本导入导出。支持修改档案名称与当前计数、删除档案；采样武器迁移为独立采样元数据，不再绑定预测目标。

每个档案最多 100 条样本、20 个搜索任务、200 个目标、20 条保存需求；最多 30 个档案，保留最近 2,000 条执行记录。执行记录每页 10 条，最新优先；完整备份包含全部保留记录。计划页向后搜索最多 10,000 次，通过二分图匹配求满足全部待获得需求的最少总强化次数，同一次强化仅分配给一条需求。历史搜索任务保留输入快照与已覆盖游标；只有最新且输入未改变的暂停任务可直接继续。修改样本需新建任务，旧结果不会被误用。

未知 counter 支持显式范围探索，每任务最多 10,000 个位置；每计算分片最多 32 个位置，种子批大小按耗时调整。范围限制不是游戏位置上限。默认种子范围沿用研究中的 0–99,999,999，UI 允许调整至 u32 范围；“唯一”仅指完成的指定范围内唯一。候选超过 2,000 时停止并要求补样／缩小范围，不静默截断后宣布唯一。

搜索每约 1.5 秒以及暂停／结束时保存。保存失败会终止运行并显示错误；重开从上一个成功保存游标继续。暂停与恢复的真实宿主行为尚待验收。

## 自动化验证

运行：仓库根 `bun run check`、`bun run build`；`tests/` 中 `bun test`。

21 项测试通过，覆盖：

- 上游重弩六抽实机 fixture 完整复现，并恢复正确种子与位置。
- TS 移植在 14 武器 × 3 属性 × 3 种子共 126 组中，与此前 WASM 差分验证过的 JS 原型预测／候选一致。此轮不是重新跑 126 组 WASM。
- 无效候选池、重复档位和类别上限拒绝。
- 续接码 u32 边界、格式校验、未知技能位置与零的区分。
- 跨 counter 分片暂停、JSON 序列化恢复，候选集合与连续搜索一致。
- 持久化失败中止，不将未保存输入标为完成。
- 完整识别 → 核对 → 回档 → 垫刀 → 采用 → 保存 → 续接流程。
- 同格冲突、拒绝候选仍推进、偏差暂停。
- 备份版本／搜索范围／观测入口校验。
- 误点修正留痕且需重新核对游戏位置。
- 同种子重新识别保留导入的技能位置，不把其他种子的技能位置嫁接过来。
- 同类加成向高级匹配，重复需求不重复消费同一槽位。
- 保存需求兼容旧档案，最短路线与穷举对照，多需求争用位置时重新分配。
- 获得状态随执行、回档和误记修正同步；单次计数与撤回不越过目标或检查点。
- 档案删除后的当前档案切换、手动计数修改、旧档案采样参数迁移。

生产构建通过，约 300 KiB；保留 Runtime Gate、平台 CSP、storage 声明及第三方许可文件。

## 浏览器交互验证

独立业务开发预览（非小黑盒 Mock）：

1. 新建档案，设置重弩／冰采样参数，逐条录入六抽实机 fixture。
2. 搜索种子 86,315,069–86,315,269、位置 475–485，唯一命中 seed 86,315,169 / counter 480。
3. 追加一条算法生成的额外验证样本完成 UI 核对（交互测试，不是新实机证据）。
4. 确认回档到 480，预测并收藏位置 483；记录三次垫刀和一次目标采用，最终位置 484。
5. 确认游戏保存检查点，导出 `GSF1-86315169-484`。
6. 另建档案导入 `GSF2-B86315169-G480-S77`，预测并记录目标未采用；位置到 481，技能位置仍为 77，导出 `GSF2-B86315169-G481-S77`。
7. 刷新页面后档案与位置恢复。
8. 约 390px 宽嵌入页面检查观星／预测／计划页面，无横向溢出。

后续设计已明确只面向 Android / iOS / 鸿蒙触屏，移除桌面平台声明和桌面专用布局。采用黑白配色、单列页面、底部导航、纵向五槽录入、自定义底部选择面板、折叠筛选和轻量保存提示；支持减少动态效果。欢迎页已移除，首次进入直接建立档案；关于移至 Header 右上角并打开独立页面。
