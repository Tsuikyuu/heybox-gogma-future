# 玩家观星操作工作流

本流程依据 [S3][S4][S5][S8] 整理。适用于通过游戏菜单试抽和回档、在外部工具记录结果的玩家。版本适用性与机制验证见 [验证表](04-sources-and-validation.md)。

补充 S11 后，推荐在 A、B 完成后使用下述种子流程；C、D 的逐格试抽仍可作为人工记录和校准方式。

## 种子预测流程（推荐）

1. 在 A 建立的 B0 上，选定武器种类与属性，连续进行完全重抽，按顺序录入每次五条加成的完整类别、档位与槽位。采样期间不要混入未记录的复原操作。
2. 使用 [GogmaSeedFinder](https://apeshinzo78.github.io/GogmaSeedFinder/) 搜索共同种子与复原位置。已知 counter 可直接填写，否则给出合理的有界范围；示例的 `475..485` 不是通用存档位置。搜索门控假设也须符合当前状态。
3. 多候选时补充连续样本；零候选时检查录入、武器/属性映射、基线与范围。不要套用示例种子。核对候选能重现全部观测前缀，并尽可能用额外一抽验证。
4. 采样后不保存回到 B0。由恢复的状态生成各武器 Reset 未来列表，筛选目标并使用 E 的共享位置与冲突规则规划；无需逐把武器试抽整张表。
5. 若要技能预测，从明确的保存点连续记录新生成的系列/组合技能对，用共同种子搜索技能 counter；旧武器上已有技能不能当作该保存点的下一抽。技能采样后同样回档，独立保存技能位置。
6. 若要 Keep/EX 优化，为每把武器录入当前从左到右的五槽类别布局。兑现 Reset 目标并保存后，使用该行之后的复原 counter 与取得的布局生成 Keep 列表。两种复原模式共用 counter。
7. 按 F 兑现，每次保存同时更新游戏状态和工具状态。已确定两条轨道时可用 `GSF2` 续接；它保存种子与两个位置，不会替玩家操作或保存游戏。

上游技能与 Keep 预测目前为公式验证状态；可先短程核对再执行长路径。搜索细节与验证范围见[种子预测专题](05-seed-prediction.md)。

## A. 准备武器与建立基线

1. 明确目标：只要技能对、只要五条数值，还是两者都要；记录可接受的替代结果。
2. 准备目标武器，核对武器种类、属性/异常、生产加成和激化方向。
3. 如需垫刀，提前准备不同激化方向的备用巨戟武器。
4. 完成计划内的巨戟升级；如要刷五条加成，完成所需前置强化。
5. **在开始试抽前手动保存游戏**，把这个存档定义为基线 B0；记录平台、游戏版本、武器状态和材料库存。
6. 明确自动保存状态和平台实际保存行为，确保后续试抽可以通过“不保存返回标题”回到 B0。若不能确认，先做两三次的小范围验证。
7. 在工具中创建 B0，技能与加成正式执行位置均设为相对值 0。

若希望观察“首次升级给出的技能”，需另建一个升级前基线，并将每次巨戟升级记作技能轨道的一次操作；不要与“已全部升级完成”的 B0 混用。

## B. 小样本校准

正式大量试抽前，使用同一武器、同一模式做 2～3 次，记录结果，不保存返回标题并重载；重复同样操作，核对结果是否一致。

再验证一次换武器共享推进：从 B0 在 A 抽一次，随后在 B 抽一次，检查是否对应单独观测 B 时的第 2 抽。

若出现不一致，先核对保存点、模式和编号，而不是继续堆材料。具体控制实验见 V1～V5。

## C. 技能观星：逐张表勘测

对每个准备观测的“武器种类 + 属性/异常”执行：

1. 从 B0 载入，确认库存与武器状态吻合。
2. 进入技能重置功能。每完成一次抽取，记录第 N 抽的**系列技能和组合技能完整名称**。
3. 记录实际支付材料、结果截图；即使不是目标也建议保留，便于检查错位。
4. 遇到目标，标记候选，不要因此覆盖 B0。可继续寻找同一武器的后备位置，解决后续同格冲突。
5. 到达预算上限或记录完目标后，选择**不保存返回标题**，重新载入 B0。
6. 换下一种武器/属性，重新从第 1 抽开始记录。

材料余量可用于辅助核对，但不要单独依赖它：匹配/非匹配支付一次分别消耗 3/6 个零件；中途换材料、炼金或购物也会污染差值。直接计数应为主，库存差为交叉检查。[S3][S4]

S4 的旧教程存在“马上保存”和“随后不保存回退”的文字歧义。本流程明确区分：**准备阶段保存 B0；试抽阶段不覆盖 B0；正式兑现后才保存成果**。

## D. 五条加成观星

建议分两段，每段有清晰的存档基线：

### D1. 先找类别组合

1. 选择完全重抽加成模式。
2. 每次记录五条的类别、档位和顺序，而非只记“3攻1属1斩”。
3. 从同一基线分别观察目标武器，找出满足类别组合且数值可接受的候选位置。
4. 回到基线，按路径兑现，核对结果后保存。

### D2. 再尝试提升档位

1. 把已取得满意类别组合的存档建立为新基线 B1。
2. 选择保留加成模式，记录输入五条组合、每次候选结果，以及是否采用候选。
3. 试抽完成后不保存回到 B1，严格重放验证过的操作路径。
4. 在目标格选择希望保留的结果，检查后保存。

保留模式和完全重抽模式共用加成轨道，但抽取候选池不同。切换模式后应使用相应公式和当前类别布局重新计算，不能直接复用另一模式的终点结果。[S11]

## E. 规划兑现顺序

1. 在同一轨道、同一基线内挑选目标，按目标位置升序排列。
2. 同一格只能分配给一把武器；遇到冲突，选择后备位置、调整优先级或继续勘测。
3. 为没有目标的空档安排垫刀武器，并逐步检查三种零件库存。
4. 显示每个目标的三项数值：**当前已抽次数、目标前垫刀次数、包含目标操作的剩余次数**。
5. 不把技能位置与加成位置混排；可以分两轮完成，降低操作负担。

示例（虚构）：目标在第 4、9、15 格。先垫 3 次，第 4 次给 A；再垫 4 次，第 9 次给 B；再垫 5 次，第 15 次给 C。总计 15 次。

## F. 正式兑现

1. 重载对应基线，切到工具的“正式执行”状态，试抽记录保持不变。
2. 每一步显示明确的游戏动作：轨道、武器实例、模式、支付材料。
3. 玩家完成一次实际操作后才确认计数推进；看见目标预告不算完成。
4. 到目标格前再核对武器，完成目标抽取，比较实际结果与记录。
5. 如一致，采用需要的结果并保存游戏；工具记录保存检查点与两个游标。
6. 若继续同一轮，沿原 B0 的绝对编号推进；保存并不会让所有表从第 1 抽重新开始。
7. 全部完成后核对目标武器、技能、五条加成和库存，保存收尾。

**工具保存记录 ≠ 游戏保存存档**。界面需要两种独立状态，不能用“记录已保存”暗示游戏成果已保存。

## G. 异常与恢复

| 场景 | 处理 |
| --- | --- |
| 试抽中误保存 | 当前存档已不是 B0；保留旧观测，记录当前位置或建立新基线，不假装回到 0 |
| 错过目标格 | 未保存且基线仍可恢复时回档重放；否则寻找后续候选 |
| 临时升级了一把巨戟武器 | 记录额外技能推进；如果此前漏记，暂停并重新校准 |
| 拒绝候选后计数不确定 | 暂停，用已观测的短序列核对；不能因“属性没变”直接减回一次 |
| 材料不足 | 先算替代支付或其他垫刀武器；若要离开本轮补材料，回来后核对存档基线 |
| 结果与观测不符 | 记录实际结果，检查版本、属性、模式、输入加成、是否漏抽/重复计数、是否真的回到同一存档 |
| 游戏更新或换角色 | 新建记录范围，旧表保留但标为未重新验证 |
| UI 误点“撤销” | 只修正工具记录；无法撤销游戏里已发生的抽取。真正回档需玩家操作游戏 |

## H. 一次观星的完成标准

- 所有保留目标都有实际结果与游戏保存检查点。
- 工具中试抽结果、执行位置和实际库存能相互对应。
- 未兑现、冲突、过期和未观测的目标状态明确。
- 下一轮可以从清晰的新基线继续，不需要靠记忆猜测第几抽。
