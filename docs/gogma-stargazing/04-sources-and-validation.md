## 1. 证据等级

- **官方确认**：CAPCOM 公告直接说明的功能、条件与补丁变化。
- **社区观测**：攻略作者的操作结果、表格和示例；足以指导验证，但不是官方算法承诺。
- **工具行为**：现有记录工具的说明，用来参考记录方式与预算；不独立证明游戏内部规则。
- **本项目推导**：由上述前提推导的计数与规划方式，应与实机条件配套使用。

## 4. 冲突与采用方式

| 问题 | 处理 |
| --- | --- |
| “同属性共表”还是“同武器种类 + 同属性共表” | 采用 S3 明确示例与 S4 的完整限定；按武器种类与属性双维度记录 |
| 两个技能是否等于两项普通技能 | 采用官方一个系列技能、一个组合技能定义；与普通技能等级区分 |
| 技能与五条加成是否一起抽 | 按 S3 分成独立轨道；旧英文文章把 reinforcement/skills 混写时不照搬 |
| “最多两个 EX” | 正确规则为同类别、同档位至多两条，不是总 EX 上限；S3 描述与用户于 2026-10-26 的确认一致，作为已确认约束 |
| 试抽后立即保存还是不保存 | 建立明确基线与分支；试抽不覆盖基线，兑现后保存，避免 S4 原文歧义 |
| 只要记录最小次数就能全拿到 | 同一位置的不同目标互斥；工具必须检测冲突，不能直接套用简单最小值贪心 |
| 拒绝新结果是否不推进 | 暂不作确定断言；记录候选生成与接受选择，实测后确定计数规则 |
| 保留模式是否只看种类和属性 | S11 公式还依赖有序五槽类别布局，不依赖旧档位；不同布局分别预测，独立实机序列仍待补充 |

## 5. 实机验证清单

所有测试都记录：游戏版本、平台、角色/基线、武器种类与属性、生产零件与激化方向、五条输入、具体模式、完整候选结果、接受/拒绝、材料前后值。未开展测试的项目状态均为**待实测**。

这里的“待实测”指本仓库的验证状态，不否认 S11 已有部分实机向量。后续接入预测还应对齐其 golden vectors，并用额外观测验证恢复的 seed/counter；不能只测试界面相对计数。

| ID | 要验证的问题 | 控制实验与通过依据 |
| --- | --- | --- |
| V1 | 同基线序列复现 | 同一基线同一武器做 3～5 次，回档原样重复，两轮完整结果逐条一致 |
| V2 | 全局推进与分表 | 先独立记录 A、B 各 3 次；回档 A 抽 1 次后 B 抽 1 次，应等于 B 原第 2 次；再换不同种类同属性对照 |
| V3 | 拒绝/取消推进 | 比较生成候选后接受、生成候选后拒绝、生成前取消三条分支的下一抽与库存，区分事件计数 |
| V4 | 技能/加成独立 | 技能试抽中插入一次加成重抽，再反向测试；两侧与基准序列分别对照 |
| V5 | 初次升级推进 | 在同一基线先升级一把巨戟武器，再对已有武器重置技能；检查是否跳至第 2 格；检查加成轨道是否受影响 |
| V6 | 激化/生产加成无关性 | 同种同属性但生产加成或激化不同的两把武器，分别回到同一基线，比较技能和完全重抽序列 |
| V7 | 保留模式依赖项 | 对比相同类别不同档位、相同类别不同顺序、不同类别组合；记录接受/拒绝路径，确定能否共用表 |
| V8 | 材料与金钱费用 | 三种激化方向分别用匹配、非匹配材料；记录点数、数量、金钱，验证混合支付与取整；区分首次升级与后续重抽 |
| V9 | 合法加成池与上限 | 在当前补丁采集各武器结果，核对 II/III/EX、属性/异常与装填差异；不能靠有限次数“没抽到”证明概率为零 |
| V10 | 外部操作与版本 | 分别插入保存/加载、任务、普通机械生产、炼金，比较序列；更新后用小样本重做 V1～V5 |
| V11 | 实际技能池 | 对照当前中文菜单及可靠数据源，建立系列/组合分组与稳定 ID，核对后来新增技能和排除项 |

建议优先完成 V1～V5、V8 后再上线自动计算正式执行次数与材料预算；未验证的条件保留人工记录能力并显示不确定状态。
