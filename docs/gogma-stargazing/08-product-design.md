# 首版需求与功能设计

日期：2026-10-26。状态：需求设计稿，尚未实现。

已确认：首版同时完整覆盖第一次观星和已有种子／续接状态的玩家。以下页面与实现顺序为设计方案。

## 1. 产品目标与首版边界

帮助《怪物猎人：荒野》玩家完成巨戟武器完全重抽观星：建立存档基线、取得种子与复原位置、预测目标、规划兑现、保存可续接状态。

两类用户共享预测与执行能力，不拆成两个产品：

- 新玩家：建立档案 → 连续采样 → 搜索 → 额外样本核对 → 回档确认 → 预测与兑现。
- 已有状态玩家：粘贴续接码或手输状态 → 预览导入 → 核对当前游戏位置 → 预测与兑现。

“完整覆盖两类玩家”指两种入口都有可完成、可恢复的闭环。首版业务轨道为 Reset（完全重抽）。技能预测、Keep／EX 优化、自动材料最优规划安排后续版本；导入的已知技能位置必须保留，不能因首版暂不使用而丢失。

## 2. 信息架构

三个主入口：观星、预测、计划。档案管理从观星页进入。

### 观星

- 无档案：首页并列“第一次观星”和“已有种子／续接码”。
- 有档案：显示当前档案、基线、识别状态、下一步操作和最近搜索任务。
- 新建档案：名称、平台、游戏版本、武器种类、属性；名称可自动生成，版本未知允许如实记录。
- 采样向导：保存基线 → 选择完全重抽 → 按序录入五槽 → 搜索设置。
- 每抽是一张五槽卡片；按武器限制显示合法类别和档位，支持编辑、删除末条及追加。
- 修改中间样本后，已有搜索结果标为待重新计算；样本连续性由玩家重新核对，不自动拼接跨基线记录。
- 手动录入优先；OCR 不作为首版依赖。

### 预测

- 顶部显示档案、当前复原位置和选中的武器／属性。
- 支持多把武器实例，名称可自定义；相同种类与属性共用预测计算，目标仍绑定具体实例。
- 按类别条数、指定档位最低条数、目标距离筛选；条件默认全部满足，页面展示可读摘要。
- 每行显示“从当前位置起第几抽”、五槽完整结果、加入计划动作。
- 展开详情展示绝对 counter 和算法版本，普通列表以玩家能执行的相对次数为主。
- 分页或窗口化显示结果；查找范围可扩展，无匹配只表示本次范围内未找到。
- 改变武器参数或当前位置后重新计算距离，已越过目标显示为已过期。

### 计划

- 目标按同一复原轨道的位置升序排列；同格只能兑现一把武器。
- 同格冲突明确显示，可保留其一或回预测页挑选后备位置；未解决时不生成含糊的执行步骤。
- 每步显示武器、模式、目标前垫刀次数、含目标的剩余次数。
- 允许手动指定垫刀武器；首版支持多武器目标排序与冲突提示，不自动宣称材料最优。
- 玩家操作后手动确认；批量记录垫刀需填写已实际完成次数，不能跨过未确认目标。
- 到目标后核对实际结果，分别记录“操作已完成”“已采用结果”“游戏已保存”。拒绝候选也消耗一次复原位置。
- 结果不一致时暂停当前计划，保留记录并进入位置核对。

## 3. 首次识别与长任务

### 搜索输入

必须明确武器、属性、同一基线的连续观测、种子范围、counter 范围和门控适用情况。初始提示准备六次完整样本，但不承诺六次必定唯一。

counter 输入提供“已知位置”“估计范围”“完全不知道”三种路径：

- 已知位置：搜索单个 counter。
- 估计范围：填写有依据的上下界，搜索前展示范围与本机估时。
- 完全不知道：解释工具无法从相对第零抽推导绝对位置，支持明确设置分段范围、逐段搜索和后续扩展；保存已覆盖范围。不预填示例中的 480，不暗示有限范围代表全域。

首版计算原型只覆盖已启用 counter gate 的 Reset。门控状态不明必须在向导中明确显示为待确认；关闭门控时 counter 不能由该观测恢复，不返回虚假的唯一位置。支持范围和确认方法需在算法接入阶段对照上游与实机补齐。

### 搜索生命周期

准备 → 运行 → 暂停／中断 → 继续 → 完成；取消结束本次任务但保留样本，可重新开始。

- 运行前短程测量本机吞吐，估时显示为估计值并随进度更新。
- 主线程分块，分块间允许页面交互；提供进度、已完成范围、候选数和暂停按钮。
- 不以找到第一个候选为完成；只在已请求范围遍历完成后报告该范围内唯一。
- 持久化完整搜索输入、算法版本、已完成分块和候选；恢复只重算未完成分块。
- 暂停在分块边界提交；页面被关闭时，最多重算最后未保存的分块，不能跳过未完成区域。
- 回到前台展示可恢复任务，不假定后台计算一直运行。
- 修改输入或算法版本后不得沿用旧进度；保留旧任务供查看，新建搜索。

### 搜索结果

| 结果 | 下一步 |
| --- | --- |
| 零候选 | 核对槽位、武器属性、连续性、基线、门控与范围；可修正输入或扩展范围 |
| 多候选 | 追加连续观测，重新过滤；展示候选对应位置 |
| 范围内唯一 | 重现全部已录样本，再提示用未参与识别的额外一抽核对 |
| 额外验证一致 | 标记已校准，引导确认游戏回到采样前基线 |
| 额外验证不一致 | 保留实际结果，返回输入与位置核对 |

允许查看未校准预测，但始终展示校准状态。开始正式执行前必须确认当前游戏位置对应哪一个检查点。

## 4. 已有状态导入

- 支持手输 seed + 下一次复原 counter、GSF1、GSF2，以及本工具完整档案文件。
- 解析后先展示 seed、复原位置、技能位置是否已知，以及缺少的武器参数。
- GSF1 不包含技能位置，按未知保存，不能填零；GSF2 的技能位置原样保留。
- 只有 seed 时可保存待定位档案，但不能假定 counter 为零后提供可执行预测。
- 续接码没有完整游戏版本、武器实例与基线历史；导入后补充必要信息并标为待核对。
- 默认导入为新档案，避免覆盖当前工作；完整档案导入前校验格式版本与字段范围，失败不修改已有数据。
- 导出明确选择游戏已保存的检查点或当前工具位置，展示两者差异。
- 仅在拥有格式所需字段时生成 GSF1／GSF2；完整备份保存样本、任务、目标和检查点。

## 5. 状态模型与计数约定

| 对象 | 内容 |
| --- | --- |
| 档案 | ID、名称、平台、游戏版本、算法版本、种子、已知／未知的双轨位置 |
| 武器实例 | ID、名称、种类、属性；后续 Keep 的五槽布局独立保存 |
| 基线／检查点 | ID、父检查点、双轨下一次 counter、玩家确认的游戏保存时间 |
| 采样批次 | 基线、武器参数、模式、有序样本、采样期间推进次数 |
| 搜索任务 | 输入快照、搜索范围、完成区间、候选、状态、版本 |
| 目标 | 基线、武器实例、绝对 counter、预测结果、兑现状态 |
| 执行记录 | 操作前后位置、武器、实际结果、是否采用、是否确认游戏保存 |

统一用“下一次操作所用 counter”保存位置。若当前位置为 C，目标 counter 为 T：

- 目标前垫刀次数 = T − C。
- 含目标的剩余次数 = T − C + 1。
- 完成目标后下一次 counter = T + 1。
- T < C 的目标已越过；T = C 表示下一抽就是目标。

采样游标、正式执行游标和最近游戏保存点分别管理。采样结束后可以确认回到基线，也可以确认从采样后位置继续，不能自动假设已回档。

工具自动保存只保存记录，游戏保存检查点只能由玩家明确确认。撤销工具误记不等于撤销游戏操作；恢复检查点也需要玩家在游戏中实际回档。更新复原位置不得改变已知技能位置。

## 6. 交互与文案原则

- 仅面向移动端触屏，五槽按顺序纵向录入，底部导航切换观星／预测／计划，不提供桌面专用布局。
- 首屏以“开始采样”“导入续接”“继续执行”等当前动作驱动。
- 普通文案使用“抽取位置”，高级详情补充 counter；区分“当前已抽次数”和“下一抽”。
- 自动保存反馈写“工具记录已保存”；游戏检查点写“你已确认游戏保存”。
- 预测、采样实测和已兑现结果使用不同状态标签，不仅依靠颜色区分。
- 空状态、输入错误、无匹配、搜索中断均提供具体下一步，保留用户输入。

## 7. 开发顺序

所有阶段属于同一首版交付，避免只实现其中一种用户入口。

1. **领域基础**：TS 算法移植与差分验证、位置约定、档案模型、续接码解析、持久化。
2. **双入口交互**：首页、档案、五槽录入、导入预览、参数校验和状态恢复。
3. **识别闭环**：分块搜索、估时、暂停续搜、候选处理、额外验证、基线确认。
4. **预测闭环**：多武器参数、未来列表、筛选、目标收藏、分页。
5. **兑现闭环**：目标冲突、逐步计数、偏差处理、游戏保存检查点、导出续接。
6. **集成验收**：小程序容器内持久化和生命周期适配、手机搜索性能、完整流程回归。

平台接口选型在接入时按官方文档确认；本设计不将浏览器实验表现视为小程序真机验收结果。

## 8. 首版验收标准

- 新玩家能够录入样本，识别范围内候选，完成额外验证与回档确认，再找到并兑现目标。
- 已有状态玩家能够导入 GSF1／GSF2，正确预测同一绝对位置，执行后导出可继续使用的状态。
- 仅有种子的玩家能够进入位置校准流程，不被错误视为 counter=0。
- 暂停、关闭、重开后恢复搜索，候选集合与一次完整搜索相同；修改输入后旧进度不能混用。
- 零候选、多候选、范围内唯一以及未完成搜索的候选均有不同状态和正确后续操作。
- 同格多武器目标冲突可解决；垫刀次数、下一抽目标和完成后位置不存在差一错误。
- 采样回档、采样后继续、目标拒绝、工具误记修正和游戏检查点恢复均不会静默重置另一轨道。
- 刷新后档案、样本、目标和执行记录保留；完整导出再导入可还原关键状态。
- 非法导入和无效五槽数据在入口被拒绝，并指出具体问题。
- 已有 Reset fixture 和差分验证通过；手机真机记录搜索耗时、交互响应、暂停恢复和容器适配结果，再确定默认范围。

## 9. 后续迭代

技能采样与位置恢复、技能未来筛选、Keep／EX 优化、材料库存与自动支付规划、OCR 录入。算法验证程度随功能展示，避免把公式一致标记成游戏实测。
