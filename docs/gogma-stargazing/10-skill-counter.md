# 技能计数器定位

## 参考与范围

本次未找到用户提及的 `gogma-skill-future` 本地目录或公开仓库，未将其描述为已阅读来源。实现依据本目录 03、05、08 的双轨设计，并对照 GogmaSeedFinder 固定提交 `65789e9aa17e434a7f5d74d18ab1f9e1365920eb` 的 `web/app.js`：`findSkillPosition`、`verifySkillObservationPrefix`、`setStateFromSkill`。

上游 Web 使用已知共同种子与连续技能对匹配有界技能 counter；零候选检查输入或范围，多候选追加观测。结果是第一条观测的位置，不能直接当作完成采样后的下一抽位置。

## 当前流程

1. 档案已有共同种子和复原位置后，在「观星 → 技能组合」建立技能采样，或手动设置已知技能位置。武器种类与属性独立于复原采样。预测页仅展示未来结果与筛选，未确定位置时引导前往技能观星。界面不要求玩家确认存档内部字段，通过额外样本核对结果。
2. 采样前保存游戏；仅录入此后连续新生成的完整技能对，至少两抽，建议四抽以上。首次巨戟升级同样消耗技能抽取，不能漏记。
3. 显式填写第一抽绝对技能 counter 的上下界（闭区间），单次最多 10,000 个位置。范围可调整后重搜；零、多、唯一候选分别展示，不声称范围外不存在其他候选。
4. 选择候选，填写紧接已录样本的新一抽。核对失败不追加；成功追加该抽并标为已核对。
5. 明确游戏是否回档：回到技能采样前，下一位置为候选本身；未回档，下一位置为候选加全部样本数（包含额外核对那一抽）。

## 状态与实现

- `Profile.skillSession` 保存种子、采样武器／属性、有序 lottery table index、搜索范围与候选、选定候选、核对及同步状态。旧档案默认 `null`。
- 建立采样将当前技能位置标为未知。追加或删除样本会清除搜索与核对结果；同步后必须建立新一轮才能继续采样。
- `searchSkillCounter` 一次跳至范围起点，生成覆盖所有候选及观测尾部的技能序列，逐候选匹配完整样本。上界与下一位置均检查 u32 范围。
- 定位只更新技能位置。复原位置对齐也保留当前技能位置；实际游戏回档若改变两个轨道，玩家须分别核对，或使用已有完整保存检查点恢复。
- 技能位置、采样和搜索结果随 JSON 备份保存；种子改变后旧采样不能继续使用。

## 验证

新增测试覆盖上游固定技能序列定位、零／多候选、端点与无效范围、错误额外样本、样本修改失效、旧种子拒绝、备份恢复、回档／未回档两种同步及复原轨道独立性。

浏览器验证：种子 `8524433`、操虫棍、雷属性，连续 table index `275,255,245,243` 在 `0..9999` 内找到 `186`；额外 `37` 核对成功，未回档同步至技能 `191`，复原仍为 `480`。

这些是公式与业务流程验证，不代表独立游戏实测。
